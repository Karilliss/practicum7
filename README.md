# Практична робота №7 — Варіант 1 (Бібліотека)

Оптимізація спискового ендпойнта `api.php?resource=books`:
профілювання, навантажувальне тестування, індекс, усунення N+1,
кешування.

## Результати «до / після»

| Показник                                | До оптимізацій | Після оптимізацій |
|-----------------------------------------|----------------|-------------------|
| Час виконання (мс)                      | 29.62          | 1.31 (cold) / 0.25 (warm) |
| Кількість SQL-запитів на HTTP-запит     | 7 (1 + 6)      | 2 (1 + GROUP BY) / 0 (warm cache) |
| Requests per second (ab -n 200 -c 20)   | 1048.73        | 1052.43           |

## Пояснення різниці

Індекс на `author` прибрав повне сканування таблиці (`type=ALL, rows=6` → `type=ref, rows=1`),
заміна запиту в циклі на один `GROUP BY` скоротила кількість SQL-запитів з 7 до 2,
а файловий кеш `listAvailable()` з TTL 60 с довів кількість SQL-запитів при гарячому кеші
до 0 і прискорив ендпойнт у ~5 разів; показник Requests per second майже не змінився,
бо на малій вибірці (6 книг) пляшковим горлом були накладні витрати Apache/PHP, а не БД.
